# RollingStone500

一个音乐榜单收藏站的项目占位。

## 现状

目前仓库只有这份 README，代码尚未开始。

## 计划做什么

一个跑在 GitHub Pages 上的纯静态站点，把音乐清单做成**工具**而不是又一份榜单镜像：

- 导入自己的清单（粘贴文本或 JSON）
- 收听进度追踪：听过 / 在听 / 想听 / 弃了，存浏览器本地
- 清单结构分析：年代分布、艺人上榜次数、各年代完成度
- 每张专辑一键跳 Apple Music（iTunes Search API 匹配真实专辑 ID，不需要 key）
- 支持多个清单分类，加新清单只丢一个 JSON

## 关于榜单数据

单条信息（某张专辑哪年发行、谁的作品）是事实，可以自由使用。但一份 500 名榜单的**完整选择与排序**是杂志的编辑成果，由数百位业内人士投票产生，完整复制并公开发布不合适 —— 维基百科作为最有动力收录它的一方，也在词条源码里明确要求不要复制榜单内容。

所以本站的做法是：

- 榜单数据由使用者自己导入，站点只提供工具
- 需要时外链到官方榜单原页
- 写自己的评论时引用单个排名（"这张排第 468"）属于正常的评论引用

真正属于本站的原创内容是**统计分析**和**跨榜单交叉结论** —— 比如同时出现在多份权威榜单里的"共识专辑"。这也是那些镜像站给不出来的东西。

## 部署方式

纯静态，无构建步骤。仓库 Settings → Pages → Source 选 **Deploy from a branch**，分支 `main`，目录 `/ (root)`。

站点地址会是 `https://<用户名>.github.io/RollingStone500/` —— 路径里有仓库名这一层，所有资源引用必须用**相对路径**，写成 `/css/style.css` 会 404。
